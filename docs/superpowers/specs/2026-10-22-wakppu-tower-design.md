# 왁뿌 타워 웹판 설계

- 작성일: 2026-10-22
- 상태: 초안 (리뷰어 확인 반영, 사용자 검토 전)
- 출처 표기
  - **(사용자)**: 사용자가 직접 말한 것
  - **(맛보기 확인)**: 사용자가 맛보기에서 직접 해 보고 받아들인 것
  - **(추측)**: 제가 추측해서 말했고 사용자가 반대하지 않은 것
  - **(제 판단)**: 제가 정한 것. 사용자가 따로 동의한 적은 없음

## 1. 한 줄 요약

브라우저에서 캐릭터를 조종해 키보드 키나 왁뿌볼 같은 발판을 밟고, ASMR 소리를 들으며 테마별 탑 꼭대기까지 오르는 3D 웹 게임이다. 로블록스 게임 'ASMR 왁뿌타'(Wax ASMR Tower)에서 아이디어를 얻었다.

## 2. 왜 만드나

- 회사에서는 앱으로 게임하기가 어렵다. 그래서 브라우저만 있으면 되는 웹 게임으로 만든다. **(사용자)**
- 요즘 ASMR과 왁스볼(왁뿌볼)이 유행이다. **(사용자)**
- 부수기만으로는 부족하다. 그래서 캐릭터로 발판을 밟으며 탑을 올라가 목표 지점에 닿으면 클리어하는 목표를 더한다. **(사용자)**
- 핵심 재미는 발판마다 다른 소리와 밟는 손맛이다. 원작 플레이 영상의 유튜버는 소리가 다양하다는 점을 가장 칭찬했다. 반대로 날카로운 소리에는 "귀가 아프다"며 볼륨을 줄였다. 좋아하는 구간을 한 번 더 들으려고 일부러 떨어지기도 했다. (원작 영상 분석)

## 3. 누가, 어떤 상황에서 하나

- 직장인이 쉬는 시간에 이어폰을 끼고 10분 남짓 한다. **(추측)**
- 설치나 회원가입 없이 링크 하나로 바로 시작하고, 다음에 다시 열면 하던 곳부터 이어서 한다. **(추측)**
- 사양이 낮은 회사 PC(내장 그래픽)에서도 버벅이지 않아야 한다. **(추측)**
- 링크를 받은 사람 중에는 휴대폰으로 여는 사람도 있다. 첫 배포를 받은 몇 명이 모바일로도 하게 해 달라고 했다. **(사용자, 2026-10-23)**
- 성공한 모습: 쉬는 시간에 몇 층 오르며 소리를 듣고 기분 좋게 창을 닫았다가, 다음 날 또 연다. **(추측)**

## 4. 목표, 하지 않을 것, 실패로 보는 것

### 4.1 첫 버전 목표

1. 테마별 탑 5개: 무지개, 얼음 콜라, 꿀, 딸기 초코, 키보드. 테마별 탑을 여러 개 두자는 건 **(사용자)**, 이 다섯 개는 제 제안에 사용자가 "그대로 진행"으로 답했다.
2. 탑마다 난이도 3단계(쉬움, 보통, 어려움). **(사용자 요청, 맛보기 확인)**
3. 캐릭터 여러 개 중에 고르기. 첫 버전은 4종. **(사용자 요청, 맛보기 확인)**
4. 발판 소리는 실제 녹음을 쓰고, 무료로 쓸 수 있는 라이선스여야 한다. **(사용자)**
5. 창을 닫았다 다시 열어도 하던 곳부터 이어 한다. **(추측)**
6. PC 브라우저에서 키보드와 마우스로 한다. **(맛보기 확인)**
7. 휴대폰과 태블릿에서는 화면 터치로 한다. 첫 버전에서는 뺐다가 배포받은 사람들의 요청으로 더했다. **(사용자, 2026-10-23)**

### 4.2 첫 버전에서 하지 않을 것

- 여럿이 같이 오르기. 나중에 필요하면 넣는다. **(사용자)**
- 상점, 재화, 유료 아이템, 꾸미기. **(추측)**
- 회원가입, 로그인, 온라인 순위표. **(추측)**
- 휴대폰용으로 따로 하는 것: 앱 설치(홈 화면에 추가), 전체 화면 버튼, 기기 기울이기 조작. 같은 주소의 같은 게임에 터치 조작만 더한다. **(제 판단)**
- 원작의 나머지 탑(벚꽃, 화창한 해변, 민트 초코). 나중 후보로 둔다. **(제 판단, 사용자 "그대로 진행")**
- 미끄러운 얼음이나 끈적한 꿀처럼 움직임 자체를 바꾸는 발판. 발판마다 반응과 소리만 다르고, 움직이는 규칙은 어느 탑에서나 같다. 맛보기로 맞춘 조작감을 탑마다 흔들지 않기 위해서다. **(제 판단)**
- 원작의 상표, 로고, 탑 이름, 발판 배치를 그대로 쓰는 것. 테마만 따오고 나머지는 직접 만든다. **(제 판단, 사용자 "그대로 진행")**

### 4.3 기술적으로 돌아가도 실패로 보는 것

- 귀가 아픈 날카로운 소리, 갑자기 튀는 큰 소리
- 같은 소리가 겹치거나 끝없이 반복되는 것 (맛보기에서 실제로 났던 버그)
- 카메라가 저절로 돌아서 조작이 답답한 것 (맛보기에서 사용자가 바꿔 달라고 함)
- 회사 PC에서 화면이 끊기거나 소리가 지직거리는 것
- 라이선스가 불분명한 소리를 쓰는 것
- 원작을 그대로 베낀 것처럼 보이는 것

## 6. 게임 설계

### 6.1 화면 흐름

시작 화면(탑 고르기) → 캐릭터와 난이도 고르기 → 플레이 → 클리어 화면

- 처음 여는 사람에게는 무지개 탑, 쉬움, 왁뿌가 미리 골라져 있다. '시작하기'를 한 번만 누르면 바로 시작한다. **(제 판단)**
- 탑 5개는 처음부터 모두 열려 있고 잠금이 없다. 쉬는 시간에 듣고 싶은 소리로 바로 가게 하려는 것이다. **(제 판단)**
- 탑 카드에는 난이도별 클리어 여부와 최고 기록이 보인다. **(제 판단)**
- 이어 할 진행이 있으면 '이어서 하기'와 '처음부터' 중에 고른다. **(제 판단)**
- 시작 화면 뒤로는 고른 탑이 천천히 돌며 보인다. **(맛보기 확인)**

### 6.2 조작과 카메라 (맛보기 확인)

- 이동은 WASD나 방향키로 한다. Space는 점프, R은 마지막 체크포인트로, M은 소리 끄기, Esc는 처음 화면이다.
- 이동 방향은 화면 기준이다. W를 누르면 화면 안쪽으로 간다.
- 카메라는 저절로 돌지 않는다. 마우스로 드래그할 때만 돌고, 휠로 줌을 한다. **(사용자: "카메라는 고정으로 해놓고 사용자가 마우스로 시점을 변경할 수 있게")**
- 예외로, 체크포인트로 돌아갈 때만 카메라가 한 번 그 체크포인트를 바라보도록 돈다. 기둥만 보이는 채로 다시 시작하지 않게 하려는 것이다. **(제 판단, 맛보기에서 반대 없음)**
- 카메라와 캐릭터 사이를 기둥이나 발판이 가리면 카메라를 앞으로 당긴다.
- 캐릭터 속도는 맛보기의 지금 값을 쓴다. 처음보다 약 15% 느리다. **(사용자: "속도를 살짝만 늦춰주고")**
- 캐릭터 바로 아래 발판에 그림자를 보여 줘서 착지 지점을 알 수 있게 한다.

터치 화면 (2026-10-23 추가, 원작 로블록스 모바일과 같은 배치) **(모두 제 판단, 사용자가 폰에서 아직 해 보지 않음)**

- 왼쪽 아래를 엄지로 누른 채 밀면 이동한다. 조이스틱은 엄지가 닿은 자리에 나타나고, 미는 만큼 빨라진다. 반지름의 20% 안은 멈춤, 70%부터 최고 속도다(`config.ts`의 `TOUCH`).
- 오른쪽 아래 버튼이 점프다. 조이스틱을 민 채로 누를 수 있다.
- 나머지 화면을 한 손가락으로 끌면 시점이 돌고, 두 손가락을 벌리거나 모으면 줌이 된다. 카메라가 저절로 돌지 않는 규칙은 같다.
- 체크포인트로, 소리 끄기, 처음 화면은 오른쪽 위 버튼으로 한다.
- 세로로 든 휴대폰은 화면 폭이 좁아 옆 발판이 안 보인다. 그래서 세로 화면에서는 세로 시야각을 넓혀(최대 80°) 정사각형 화면만큼의 좌우 폭을 남기고, 시작 화면에서 가로로 돌리면 더 넓게 보인다고 알려 준다. 가로 화면과 PC의 시야각은 그대로다.
- 처음부터 터치 화면(마우스 올리기가 없고 손가락으로 누르는 화면)이면 터치 조작을 보여 준다. 터치 노트북처럼 그 밖의 기기도 손가락이 화면에 닿는 순간 보여 준다. 키보드는 언제나 같이 쓸 수 있다.

### 6.3 캐릭터

- 4종이다. 금빛 햄스터 **햄찌**(기본), 하얀 토끼 **깡충이**, 노란 병아리 **삐약이**, 귀와 꼬리가 있는 **냥냥**. 처음에는 왁뿌, 키캡이, 반투명 젤리였는데, 사용자가 2026-10-22에 젤리는 "너무 못생겼어"라며 바꿔 달라고 했고(→ 삐약이), 왁뿌는 햄스터로, 키캡이는 토끼로 바꿔 달라고 했다. **(사용자 요청)**
- 모양만 다르고 크기, 충돌 판정, 능력은 모두 같다. **(제 판단, 맛보기에서 반대 없음)**
- 맛보기의 첫 캐릭터를 보고 사용자가 "너무 못생겼어"라고 했다. 실제 게임에서는 단순한 도형으로 만드는 방식은 유지하되 더 귀엽게 다듬고, 사용자에게 모습을 보여 확인받는다.
- 고른 캐릭터는 브라우저가 기억한다.

### 6.4 난이도

'올라가기 힘들게'를 아래 네 가지로 해석했다. **(제 판단, 맛보기에서 반대 없음)**

| | 점프 간격 | 단차 | 체크포인트 | 깨지는 발판 |
|---|---|---|---|---|
| 쉬움 | 기준 | 기준 | 가장 많음 | 깨진 뒤에도 남는다 |
| 보통 | 1.25배 | 1.15배 | 쉬움의 절반쯤 | 깨진 뒤에도 남는다 |
| 어려움 | 1.45배 | 1.3배 | 가장 적음 | 깨지고 0.7초 뒤 무너지기 시작해 약 0.95초 만에 사라진다 |

- 어려움의 무너지는 속도는 사용자 요청으로 빨라졌다. **(사용자: "어려움 때 왁뿌볼이 조금 더 빠르게 사라지면 좋겠어")**
- 키보드 계단이나 다리처럼 붙어서 걷는 구간은 난이도와 관계없이 간격이 같다. 타건하며 걷는 맛을 지키기 위해서다. **(맛보기 확인)**
- 무너진 발판도 10초 뒤 돌아온다.
- 맛보기의 어려움에는 체크포인트가 출발점뿐이었다. 실제 탑은 더 길기 때문에, 어려움에서도 떨어졌을 때 다시 올라야 하는 분량이 3~4분을 넘지 않게 체크포인트를 둔다. **(제 판단)**

### 6.5 발판의 공통 규칙

발판은 아래 다섯 가지 동작 중 하나를 따른다. 탑마다 모양과 소리만 바꿔 입힌다. **(제 판단, 맛보기 구조를 일반화)**

| 동작 | 밟을 때 | 서 있는 동안 | 발을 뗄 때 | 맛보기의 예 |
|---|---|---|---|---|
| 키 | 눌리는 연출, 누르는 소리 | 없음 | 떼는 소리 (손가락을 떼듯 50~60ms 늦게) | 키보드 계단, WAKPPU 다리 |
| 깨지는 발판 | 처음 밟으면 조각이 튀며 깨지는 연출과 깨지는 소리. 높이가 조금 낮아진 채 남는다. 다시 밟으면 말랑한 소리 | 없음 | 없음 | 왁뿌볼 |
| 말랑 발판 | 찌그러졌다 튕기는 연출, 말랑한 소리 | 없음 | 없음 | 탄산 젤리에 착지할 때 |
| 머무는 발판 | 착지 소리 | 이어지는 소리와 연출(기포 등) | 이어지는 소리가 멈춘다 | 탄산 젤리 |
| 체크포인트, 꼭대기 | 저장 효과음과 '체크포인트 저장' 표시 / 축하 효과음과 클리어 | 없음 | 없음 | 꽃무늬 받침, 트로피 |

- 한 번 밟으면 소리는 정확히 한 번 난다. 두 발판 경계에 서 있거나 경계를 지나가도 다시 나지 않는다. 맛보기에서 생긴 버그를 고치면서 나온 기준이다. **(맛보기 확인)**
- 키가 눌리는 건 화면 연출일 뿐이고, 충돌 판정의 높이는 바뀌지 않는다. 캐릭터와 그림자만 키와 같이 내려가 보인다.
- 깨진 발판은 10초 뒤 원래대로 돌아온다. 그때 캐릭터가 위에 서 있으면 내려간 다음에 돌아온다. **(사용자: "10초쯤 뒤에 다시 원래대로", 위에 서 있을 때의 처리는 제 판단)**
- 같은 발판을 연달아 밟아도 같은 소리로 들리지 않게 한다. 녹음 조각 여러 개 중 하나를 무작위로 고르고, 높낮이와 좌우 위치를 조금씩 바꾼다. **(맛보기 확인)**

### 6.6 탑 5개

**공통**

- 맛보기처럼 가운데 기둥을 나선으로 감으며 오르는 열린 구조를 쓴다. 원작은 사각 탑 안쪽을 오르지만, 카메라가 벽에 막히지 않도록 맛보기 구조를 유지한다. **(제 판단, 사용자는 맛보기에 "다 마음에 드는데"라고 함)**
- 탑마다 색, 기둥 무늬, 하늘, 체크포인트 모양을 테마에 맞춘다.
- 길이는 쉬움 기준으로 한 탑에 5~8분, 체크포인트 사이는 1~2분이다. 무지개 탑만 입문용으로 조금 짧고 쉽게 만든다. **(제 판단)**

### 6.7 체크포인트, 이어 하기, 기록

- 체크포인트에 닿으면 저장음이 나고 '체크포인트 저장'이 잠깐 뜬다. **(맛보기 확인)**
- 바닥보다 한참 아래로 떨어지면 마지막 체크포인트에서 다시 시작한다. **(맛보기 확인)**
- 탑과 난이도마다 마지막 체크포인트, 걸린 시간, 밟은 발판 수를 브라우저에 저장한다. 창을 닫았다 다시 열어도 이어서 할 수 있다. **(추측을 제 판단으로 구체화)**
- 깨진 발판 상태는 저장하지 않는다. 다시 열면 모두 원래대로 돌아와 있다. **(제 판단)**
- 클리어하면 걸린 시간과 밟은 발판 수를 보여 주고, 최고 기록을 갱신했으면 알려 준다. 기록은 그 브라우저에만 남는다. **(제 판단)**
- 클리어 화면에는 '처음부터 다시', '탑 고르기', '계속 둘러보기'가 있다. **(맛보기 확인, '탑 고르기'만 추가)**
- 다른 탭으로 가거나 창이 가려지면 시간과 이어지는 소리가 멈춘다. **(제 판단)**

### 6.8 화면 표시와 설정 (맛보기 확인)

- 왼쪽 위: 지금 높이와 꼭대기 높이(m), 진행 막대, 밟은 발판 수, 시간, 난이도
- 오른쪽 위: 소리 크기 슬라이더(처음 70%), 소리 끄기(M), 체크포인트로(R), 처음 화면(Esc)

- 시작 화면에 소리 출처를 적는다.

## 7. 소리

### 7.1 원칙

- 소리가 이 게임의 주인공이다. 발판 소리는 실제 녹음을 쓴다. 맛보기에서 합성 소리로는 "아까보단 낫지만 키보드 소리는 아니다"가 한계였고, 녹음으로 바꾸자 "타건소리는 좋아졌고"라는 반응이 나왔다. **(맛보기 확인)**
- 라이선스는 CC0를 우선한다. 알맞은 CC0가 없으면 출처만 밝히면 되는 CC BY까지 허용한다. 비상업(NC)과 변경 금지(ND) 조건이 붙은 소리는 쓰지 않는다. **(제 판단)**
- 원하는 소리의 녹음이 없으면 결이 가장 비슷한 녹음을 쓴다. 예를 들어 왁스볼 녹음은 CC0로 없어서 마른 달걀 껍데기가 부서지는 녹음을 썼다. **(맛보기 확인)**
- 소리 하나는 녹음 1개에서 한 번씩 잘라 낸 조각 5~10개로 만들고, 조각끼리 음량을 맞춘다. **(맛보기 확인)**
- 최종 출력에 컴프레서를 걸어 튀는 소리를 누른다. 소리 크기 조절과 음소거를 둔다. **(맛보기 확인)**
- 소리 파일을 못 불러와도 게임은 계속되고, 그 소리만 합성 소리로 대신 낸다. **(맛보기 확인)**
- 브라우저 정책 때문에 첫 클릭('시작하기')을 할 때 소리를 켠다.
- 탑에 들어갈 때 그 탑의 소리만 불러온다. **(제 판단)**
- 점프, 착지, 체크포인트, 클리어 같은 효과음은 맛보기처럼 합성 소리여도 된다. 거슬린다는 의견이 나오면 녹음으로 바꾼다. **(제 판단)**
- **소리는 사용자가 직접 듣고 확인한다.** Claude는 소리를 들을 수 없다. 탑마다 소리를 넣고 나면 사용자가 들어 보고 괜찮다고 해야 그 탑의 소리 작업이 끝난다.
- 소리 후보는 Claude가 찾아서 내려받고, 잘라서 음량을 맞춘다. 맛보기 때처럼 사용자는 듣고 고르기만 한다. **(사용자: "무료로 쓸 수 있는 소리를 찾아와줘")**
- 음질은 모든 소리에 Freesound 미리듣기 품질을 기본으로 쓴다. 사용자가 이 품질로 맛보기 소리를 듣고 좋다고 했기 때문이다. 듣다가 음질이 거슬리는 소리만 원본 WAV로 바꾸고, 그때는 사용자의 Freesound 무료 계정이 필요하다. **(제 판단)**
- 결이 비슷한 다른 녹음까지 써 봐도 사용자가 듣기에 아니라면, 그 발판을 소리가 통과하는 다른 재료의 발판으로 바꾼다. 발판 소리를 합성 소리로 때워서 내보내지는 않는다. 소리 하나 때문에 탑 하나가 통째로 멈추지 않게 하려는 것이다. **(제 판단)**

## 8. 기술 **(모두 제 판단)**

- 이미 만들어 둔 프로젝트(Vite, React 19, TypeScript, React Compiler, yarn) 위에 만든다.
- 3D는 맛보기에서 검증한 Three.js를 쓴다.
- 게임 핵심(장면, 물리, 발판, 소리, 게임 루프)은 React 바깥의 TypeScript 모듈로 만들고, 탑 고르기, 화면 표시, 클리어 같은 화면은 React로 만든다. 맛보기처럼 물리와 루프를 직접 돌리면 React 렌더링과 섞이지 않아 단순하고 빠르다. react-three-fiber는 쓰지 않는다.
- 물리 엔진 라이브러리는 쓰지 않는다. 맛보기의 간단한 충돌 처리(원기둥 모양 캐릭터와 회전한 상자 발판)를 이어 쓴다.
- 서버는 없다. 정적 파일로 빌드되므로 어디에든 올릴 수 있다.
- 저장은 브라우저의 localStorage에 `wakppu.` 접두사로 한다. 저장이 막힌 브라우저에서도 게임은 된다.
- 대상 브라우저는 최신 Chrome과 Edge(회사 PC 기준)다. Safari와 Firefox는 돌아가면 좋은 정도다.
- 휴대폰은 최신 iOS Safari와 Android Chrome이 대상이다. 개발하는 Mac에서는 실제 폰을 못 쓰므로 헤드리스 Chrome의 모바일 에뮬레이션(`tools/checks/touch-*.json`)으로 확인하고, 실제 손맛과 성능은 사용자가 폰에서 확인한다. **(제 판단)**
- 성능 목표는 내장 그래픽 노트북의 Chrome에서 끊김 없이(60fps 가까이) 도는 것이다. 실시간 그림자 대신 맛보기의 가짜 그림자를 쓰고, 같은 모양 발판은 묶어서 그리고, 픽셀 비율에 상한을 둔다.
- 성능의 출발점은 맛보기다. 사용자는 맛보기를 9번 고쳐 가며 하는 동안 화면이 끊긴다는 말을 한 적이 없다. 그래서 맛보기보다 무겁게 그리지 않는 것을 기본으로 한다.
- 성능 합격 기준: 디버그 표시(예: 주소 뒤에 `?debug`)로 초당 프레임과 프레임 시간을 보여 준다. 탑 하나를 오르는 동안 평균 55fps 이상이고 50ms를 넘는 프레임이 거의 없으면 합격이다. 첫 탑(무지개 탑)을 만든 직후에 한 번 재고, 탑을 더할 때마다 다시 잰다. 사용자가 사양 낮은 회사 PC를 쓸 수 있으면 거기서도 잰다. **(제 판단)**
- 만드는 중간 결과는 맛보기 때처럼 비공개 Artifact 링크로 올린다. 사용자는 이 링크로 이 Mac이든 다른 PC든 바로 해 볼 수 있다. 로컬 개발 서버(`yarn dev`)로도 확인한다. 맛보기 링크는 그대로 두고 새 링크를 쓴다. **(제 판단)**
- WebGL을 못 쓰는 브라우저에서는 안내 문구를 보여 준다. **(맛보기 확인)**

### 9.2 버그에서 배운 것

- 키가 눌릴 때 충돌 높이까지 내리면, 두 키 경계에 선 캐릭터가 옆 키를 턱으로 보고 올라섰다 되돌아오기를 초당 170번쯤 되풀이했다. 그때마다 누르는 소리가 나서 소리가 끝없이 반복됐다. 그래서 눌림은 연출로만 처리한다.
- 턱을 오르는 범위와 서 있다고 판정하는 범위가 다르면, 계단을 오를 때 키 하나에 누르는 소리가 3~4번 났다. 두 범위를 같게 맞춘다.
- 확인 기준: 두 키 경계에 3초 서 있어도 서 있는 발판 판정이 바뀌는 횟수는 처음 착지를 포함해 2번 이하다. 계단을 오르면 키마다 누르는 소리가 정확히 한 번 난다.

### 9.3 조작에서 배운 것

- 저절로 도는 카메라는 올라가기 힘들었다. 카메라는 마우스로만 돌린다.
- 3D에서는 발판까지 거리가 잘 안 느껴진다. 착지 지점 그림자가 꼭 필요하다.

2. 탑 고르기, 이어 하기, 기록
